# Go-сервер пользователей

Порт Flask-сервера `api.py` на Go с тем же HTTP API: создание пользователей, получение их данных и учёт активных пользователей. Данные хранятся в SQLite.

## Структура

```
go-server/
├── cmd/server/main.go          точка входа: сборка зависимостей, запуск и остановка сервера
├── internal/
│   ├── config/                 настройки из флагов и переменных окружения
│   ├── models/                 модели данных: User, запросы и ответы API
│   ├── storage/                SQLite: подключение, схема, репозиторий пользователей
│   ├── validation/             проверка и нормализация входных данных
│   ├── activity/               потокобезопасный список активных пользователей
│   ├── handlers/               HTTP-обработчики эндпоинтов
│   ├── router/                 маршруты: URL → обработчик
│   ├── middleware/             промежуточные обработчики (логирование запросов)
│   ├── respond/                утилиты для JSON-ответов и ошибок
│   └── docs/                   страница Swagger UI и спецификация, встроенные в бинарник
├── go.mod, go.sum              зависимости
└── README.md
```

Пакеты в `internal/` нельзя импортировать из других Go-модулей — это внутренняя реализация сервера.

### Как связаны пакеты

```
cmd/server ──► config
    │
    ├────────► storage ──► models
    ├────────► activity
    └────────► router ──► middleware, docs
                  │
                  ▼
               handlers ──► validation, respond, models
```

- `cmd/server` создаёт все зависимости (база, репозиторий, трекер) и передаёт их в обработчики — больше нигде глобального состояния нет.
- `handlers` зависят не от конкретных `storage` и `activity`, а от интерфейсов `UserStore` и `ActiveTracker` (`internal/handlers/handler.go`). Хранилище можно заменить, например, на PostgreSQL или на заглушку в тестах, не трогая обработчики.
- Сообщения об ошибках валидации задаются в `validation` и без изменений уходят клиенту.

### Куда добавлять новый код

| Задача | Что менять |
|--------|------------|
| Новый эндпоинт | метод в `handlers/`, строка в `router/router.go` |
| Новое поле пользователя | `models/user.go`, схема в `storage/sqlite.go`, запросы в `storage/users.go` |
| Новое правило валидации | `validation/` |
| Новая настройка | `config/config.go` |
| Сквозная логика для всех запросов (CORS, авторизация) | новый файл в `middleware/`, подключение в `router/router.go` |
| Изменения в API | `../openapi.yaml`, затем скопировать его в `internal/docs/` (тест `TestFilesInSync` проверяет, что копия совпадает) |

Единственная внешняя зависимость — [`modernc.org/sqlite`](https://pkg.go.dev/modernc.org/sqlite), драйвер SQLite на чистом Go. Ему не нужны CGO и C-компилятор, поэтому сервер собирается на Windows без дополнительной настройки.

## Требования

- Go 1.26 или новее ([скачать](https://go.dev/dl/)). Если установлена версия от 1.21 до 1.25, Go сам скачает нужный toolchain при первой сборке (нужен доступ в интернет).

Проверить установку:

```powershell
go version
```

## Запуск

Все команды выполняются из директории `go-server`.

```powershell
cd go-server
go run ./cmd/server
```

Справка по флагам: `go run ./cmd/server -h`.

При первом запуске Go скачает зависимости. Сервер стартует на `http://127.0.0.1:5000` и создаёт в текущей директории файл `test.db`. Остановка — Ctrl+C: сервер дождётся завершения текущих запросов (до 10 секунд).

### Сборка исполняемого файла

```powershell
go build -o server.exe ./cmd/server
.\server.exe
```

На Linux/macOS:

```bash
go build -o server ./cmd/server
./server
```

Готовый бинарник самодостаточен: Go и исходники для запуска не нужны.

### Настройки

| Флаг | Переменная окружения | По умолчанию | Описание |
|------|----------------------|--------------|----------|
| `-addr` | `ADDR` | `127.0.0.1:5000` | Адрес и порт сервера |
| `-db` | `DB_PATH` | `test.db` | Путь к файлу SQLite |

Флаг имеет приоритет над переменной окружения.

```powershell
.\server.exe -addr 0.0.0.0:8080 -db C:\data\users.db

$env:ADDR = "127.0.0.1:8080"; .\server.exe
```

Адрес `127.0.0.1` принимает подключения только с этого компьютера. Чтобы сервер был доступен из сети, используйте `0.0.0.0:<порт>` и разрешите порт в брандмауэре.

## Docker

```bash
docker build -t users-api-go .
docker run -d --name users-api -p 5000:5000 -v users-data:/data users-api-go
```

В контейнере сервер слушает `0.0.0.0:5000`, база хранится в томе `/data`. Запуск обеих версий через Docker Compose и скрипт проверки эндпоинтов описаны в [основном README](../README.md#быстрый-старт), развёртывание на сервере — в [DEPLOY.md](../DEPLOY.md).

## HTTP API

Все ответы — JSON. Ошибки имеют вид `{"error": "описание"}`.

Интерактивная документация открывается в браузере по адресу `/docs` запущенного сервера, например [http://localhost:5000/docs](http://localhost:5000/docs); на ней каждый эндпоинт можно вызвать кнопкой **Execute**. Полная спецификация в формате OpenAPI 3.1 — [`../openapi.yaml`](../openapi.yaml), общая для Go- и Flask-версий. Как её просматривать, описано в [основном README](../README.md#http-api).

| Метод и путь | Описание | Успех | Ошибки |
|--------------|----------|-------|--------|
| `POST /adduser` | Создать пользователя | 201 `{"id": 1, "name": "Alice"}` | 400 |
| `GET /user/{id}` | Получить пользователя | 200 `{"id": 1, "name": "Alice"}` | 404 |
| `POST /user/{id}/active` | Отметить пользователя активным | 200 `{"active": [3, 1]}` | 404 |
| `GET /active` | Список активных пользователей | 200 `{"active": [3, 1]}` | — |

Подробности:

- **`POST /adduser`** принимает тело `{"name": "Alice"}`. Тело должно быть JSON-объектом не больше 1 МБ, `name` — непустой строкой до 100 символов. Пробелы по краям имени обрезаются.
- **`GET /user/{id}`** и **`POST /user/{id}/active`** возвращают 404, если пользователя нет или `id` не целое число.
- **Список активных** хранит последние 5 отметок; новая отметка вытесняет самую старую. Список живёт в памяти процесса и очищается при перезапуске сервера.
- Запрос с неподдерживаемым методом (например, `GET /adduser`) получает 405, неизвестный путь — 404 (текстовый ответ, не JSON).

### Примеры: PowerShell

Windows PowerShell 5 по умолчанию отправляет строку тела не в UTF-8, из-за чего кириллица превращается в `?`. Передавайте тело байтами UTF-8:

```powershell
$base = "http://127.0.0.1:5000"
$body = [Text.Encoding]::UTF8.GetBytes('{"name": "Алиса"}')
Invoke-RestMethod -Method Post "$base/adduser" -ContentType 'application/json; charset=utf-8' -Body $body

Invoke-RestMethod "$base/user/1"
Invoke-RestMethod -Method Post "$base/user/1/active"
Invoke-RestMethod "$base/active"
```

В PowerShell 7 (`pwsh`) достаточно `-Body '{"name": "Алиса"}'`.

### Примеры: curl

```bash
curl -X POST http://127.0.0.1:5000/adduser -H "Content-Type: application/json" -d '{"name": "Alice"}'
curl http://127.0.0.1:5000/user/1
curl -X POST http://127.0.0.1:5000/user/1/active
curl http://127.0.0.1:5000/active
```

В `cmd.exe` кавычки внутри JSON нужно экранировать: `-d "{\"name\": \"Alice\"}"`.

## Логи

Каждый запрос пишется в stderr: метод, путь, статус и время обработки.

```
2026/10/13 14:28:44 listening on http://127.0.0.1:5000 (database: test.db)
2026/10/13 14:28:47 POST /adduser 201 7.191ms
2026/10/13 14:28:47 GET /user/42 404 999µs
```

Внутренние ошибки (например, сбой БД) логируются с подробностями, а клиент получает только `500 {"error": "internal server error"}`.

## Тесты

```powershell
go test ./...
go vet ./...
go test ./internal/router/...   # тесты одного пакета
```

| Пакет | Что проверяют тесты |
|-------|---------------------|
| `router` | Все эндпоинты целиком через HTTP: коды ответов, валидация, SQL-инъекции, параллельные запросы |
| `storage` | Создание, чтение и проверка существования пользователей |
| `validation` | Правила для имени: обрезка пробелов, пустое имя, длина в символах |
| `activity` | Вытеснение старых отметок, независимость возвращаемой копии, конкурентный доступ |
| `config` | Значения по умолчанию, приоритет флагов над переменными окружения |

Тесты используют временную БД и не трогают `test.db`. Проверка на гонки данных `go test -race ./...` требует CGO и установленного C-компилятора (например, MinGW-w64 на Windows).

## Отличия от Flask-версии

- HTTP API и формат ответов совпадают с `api.py`; существующую базу `test.db` можно использовать в обеих версиях.
- `POST /adduser` разбирает тело как JSON независимо от заголовка `Content-Type`; Flask-версия без `Content-Type: application/json` отвечает 400.
- Ответы на неизвестные пути и неподдерживаемые методы — текстовые, как и во Flask (там HTML).
- Встроенный HTTP-сервер Go пригоден для продакшена, отдельный WSGI-сервер не нужен. Таймауты чтения и записи уже настроены.
- Запись в SQLite идёт через одно соединение: SQLite допускает только одного писателя, так что запросы на запись выполняются по очереди.
